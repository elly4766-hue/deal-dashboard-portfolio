# E-commerce Deal Performance Dashboard

이커머스 딜특가 운영 데이터를 기반으로  
상품 선정과 운영 성과 분석을 지원하기 위해 제작한 **Python / Streamlit 기반 분석 대시보드**입니다.

실제 업무에서는 Google Sheet 기반 데이터를 활용했으며,  
본 포트폴리오 버전은 회사 데이터와 완전히 분리된 **가상 데이터**로 구성했습니다.

---

## 1. Project Overview

딜특가 편성 업무에서는 특정 상품을 편성할지 판단하기 위해  
과거 상품 성과뿐 아니라 브랜드, 카테고리, 가격대, 할인율, 요일, 전시순서 등 여러 정보를 함께 확인해야 합니다.

기존에는 여러 시트와 과거 편성 이력을 직접 확인해야 했기 때문에  
비교 가능한 정보를 빠르게 정리하는 데 시간이 많이 들었습니다.

이에 Python과 Streamlit을 활용하여 데이터를 정제하고,  
상품 단위 의사결정부터 전체 딜특가 운영 성과까지 하나의 화면에서 분석할 수 있도록 대시보드를 구축했습니다.

이 프로젝트의 목적은 데이터를 기반으로 자동으로 최종 상품을 선정하는 것이 아니라,

> **과거의 비교 가능한 성과를 빠르게 제공하여 실무자의 판단을 지원하는 것**

입니다.

## 2. Dashboard Structure

대시보드는 분석 목적에 따라 5개 영역으로 구성했습니다.

### Overview

딜특가 전체 성과를 빠르게 확인하는 화면입니다.

- 기간 총 매출
- 일평균 매출
- 편성당 평균 매출
- 편성 수
- 월별 편성 효율 추이
- 카테고리 매출 기여도
- 브랜드 총매출 TOP 10
- 브랜드 효율 TOP 10

---

### 운영·추이 분석

딜특가 운영 시점과 편성 방식에 따른 성과 차이를 분석합니다.

- 일별 매출 추이
- 요일별 편성 효율
- 전시순서별 편성 효율
- 브랜드 기간별 성과 변화

브랜드 성과 변화 분석에서는 비교 기간을 선택할 수 있도록 구성했습니다.

- 최근 1개월 vs 이전 1개월
- 최근 3개월 vs 이전 3개월
- 최근 6개월 vs 이전 6개월
- 최근 12개월 vs 이전 12개월

또한 분석 목적에 따라 정렬 기준을 변경할 수 있습니다.

- 증감률 높은 순
- 증감률 낮은 순
- 최근 편성당 평균 매출
- 최근 총매출
- 최근 편성 수
- 편성당 평균 매출 증가액

---

### 카테고리 성과 분석

대카테고리 및 중카테고리 단위로 성과를 비교합니다.

주요 지표는 다음과 같습니다.

- 편성 수
- 편성당 평균 매출
- 평균 결제수량
- 평균 할인율

기간을 선택하여 특정 시점의 카테고리 성과도 비교할 수 있습니다.

---

### 가격·혜택 분석

상품의 최종 혜택가와 할인율에 따른 성과 차이를 분석합니다.

- 혜택가 가격대별 성과
- 할인율 구간별 성과
- 편성당 평균 매출
- 평균 결제수량
- 편성 수
- 평균 혜택가

또한 **혜택가 가격대 × 할인율 조합 매트릭스**를 구성하여  
어떤 가격·할인 조합에서 상대적으로 높은 성과가 발생했는지 확인할 수 있도록 했습니다.

각 셀에는 평균 매출뿐 아니라 편성 횟수 `n`을 함께 표시하여  
표본 수가 적은 결과를 과도하게 해석하지 않도록 설계했습니다.

---

### 상품 검색

상품코드를 검색하여 특정 상품의 과거 편성 성과를 확인할 수 있습니다.

주요 KPI:

- 편성 횟수
- 편성당 평균 매출
- 평균 결제수량
- 평균 할인율

또한 해당 상품의 성과를 다음 비교군과 함께 확인할 수 있습니다.

- 동일 브랜드
- 동일 중카테고리
- 동일 혜택가 가격대

복수의 상품코드가 하나의 셀에 존재하는 경우에도  
매출을 여러 행으로 분리하지 않고 하나의 딜로 유지했습니다.

대표상품코드를 별도로 생성하고 전체 옵션코드 검색 매핑을 구성하여  
어떤 옵션코드로 검색하더라도 동일 상품의 과거 이력을 확인할 수 있도록 설계했습니다.

## 3. KPI Design

초기에는 PV, CVR, PV당 매출 등 트래픽 지표를 중심으로 분석을 구성했습니다.

하지만 실제 딜특가 운영에서는 편성 성과를 판단할 때  
트래픽 자체보다 **실제 발생한 매출과 판매 성과**가 더 중요한 기준이라고 판단했습니다.

이에 메인 KPI를 다음과 같이 재설계했습니다.

- 편성 수
- 편성당 평균 매출
- 평균 결제수량
- 평균 할인율

특히 총매출만으로 성과를 비교하면  
편성 횟수가 많은 기간이나 브랜드가 자연스럽게 높게 나타날 수 있습니다.

따라서 다음 두 개념을 분리했습니다.

- **규모 지표:** 총 매출
- **효율 지표:** 편성당 평균 매출

PV 관련 지표는 핵심 성과 지표가 아니라  
필요 시 원인을 진단하기 위한 보조지표로 분리했습니다.

## 4. Data Processing

Python과 pandas를 활용해 RAW 데이터를 분석 가능한 형태로 정제했습니다.

주요 처리 과정은 다음과 같습니다.

- Google Sheet RAW 데이터 로드
- 상품코드 정제
- 복수 옵션코드 처리
- 대표상품코드 생성
- 숫자형 데이터 변환
- 날짜 데이터 변환
- 성과완료 / 예정편성 구분
- 할인율 및 실질 할인율 계산
- 혜택가 가격대 분류
- 브랜드명 표준화
- 상품 카테고리 분류
- 상품 MASTER 결합

성과 데이터와 예정 편성 데이터는 구분하여 처리했습니다.

결제수량 또는 결제금액이 입력된 경우 `성과완료`,  
두 값이 모두 비어 있는 경우에만 `예정편성`으로 판단하도록 구성했습니다.

숫자 `0`은 실제 입력된 값으로 간주하여 성과완료로 처리합니다.

## 5. Product Code Handling

실제 데이터에서는 하나의 딜에 여러 상품코드가 입력되는 경우가 존재했습니다.

예를 들어 색상이나 옵션이 다른 동일 상품이 여러 코드로 관리될 수 있습니다.

이 경우 상품코드를 각각 별도 행으로 분리하면  
동일한 매출이 여러 번 집계될 위험이 있습니다.

따라서 다음 방식으로 처리했습니다.

- 원본 딜 행은 하나로 유지
- 첫 번째 상품코드를 대표상품코드로 사용
- 전체 옵션코드를 별도로 저장
- 검색 시 모든 옵션코드를 대표상품과 연결

이를 통해 **매출 중복 집계 없이 옵션코드 검색 기능을 동시에 구현**했습니다.

## 7. Key Analysis Decisions

### 1) 총매출과 편성 효율을 구분

월별 또는 브랜드별 총매출은 편성 횟수가 많을수록 증가할 가능성이 높습니다.

따라서 총매출만으로 성과를 비교하면  
실제 상품 한 번의 편성 효율을 파악하기 어렵습니다.

이에 다음과 같이 구분했습니다.

- 총 매출 → 전체 매출 규모 파악
- 편성당 평균 매출 → 1회 편성의 평균적인 성과 파악

---

### 2) 평균값은 표본 수와 함께 해석

평균 매출이 높더라도 편성 횟수가 1~2회에 불과하면  
특정 고성과 편성에 의해 결과가 크게 달라질 수 있습니다.

따라서 분석 과정에서 다음 기준을 적용했습니다.

- 일부 브랜드 효율 분석에 최소 편성 횟수 적용
- 기간 비교 시 양쪽 기간 모두 일정 횟수 이상 편성된 브랜드 비교
- 가격 × 할인율 매트릭스에 편성 횟수 `n` 표시

이를 통해 평균값만 보고 성과를 과도하게 판단하지 않도록 했습니다.

---

### 3) 상관관계를 인과관계로 해석하지 않음

요일, 할인율, 전시순서와 매출 사이에 차이가 나타나더라도  
해당 변수 하나가 매출 변화의 직접적인 원인이라고 단정하기 어렵습니다.

성과에는 다음과 같은 요인이 동시에 영향을 줄 수 있습니다.

- 브랜드 파워
- 상품 경쟁력
- 시즌
- 프로모션 규모
- 가격
- 할인율
- 재고
- 편성 전략

특히 전시순서의 경우  
원래 성과가 좋을 것으로 예상되는 상품을 앞쪽에 배치했을 가능성도 존재합니다.

따라서 해당 분석은 인과관계를 증명하기 위한 것이 아니라  
**운영 패턴을 확인하고 추가적인 판단 근거를 제공하는 용도**로 활용했습니다.
